# Issue #88: LTE-M 電源遮断をロードスイッチ IC に置き換える設計案

対象Issue: https://github.com/makeOurCity/parking-status-sensor/issues/88

**種類: 作業記録ドキュメント（暫定・WIP）。** 設計案と、ベンチで確認する項目をまとめたもの。実機では未検証。

## 1. 方針

LTE-M モジュール（M5 Unit CatM U128）の VCC 線を開閉する部品を、**ラッチングリレー（Seeed Grove 2-Coil、5V コイル品）から、ロードスイッチ IC に替える**。

理由（調査結果は #88 のコメントを参照）:

- 5V コイルのリレーを、電池駆動の 3.3V で動かしており、定格外（SET コイルは約 2.6V の見積り）。3.3V のラッチングリレーの完成品は、Adafruit #2923 しか見つからなかった。
- 低電圧の電源ゲートの定番は、ロードスイッチ IC（TI、Particle Boron、SparkFun の技術者の発言、Adafruit の設計）。ラッチングリレーでモデムの電源を切る公開事例は、見つからなかった。
- ロードスイッチは**ステートレス**。ON ピンにプルダウンを付ければ、MCU のリセット・Deep Sleep・GPIO の Hi-Z・電源喪失のどれでも自動的に OFF になる。状態が MCU の外に残らないので、「リレーが切り替わらない」「ON のまま戻らない」という故障モードがない。起動時の安全パルスも不要。

設計思想（Grove の汎用モジュールをケーブルでつなぐ）からの**例外**は、現行のリレーと同じ規模（VCC 線を途中で挟む）にとどめる。

## 2. 部品: TI TPS22918（SOT-23-6）

出典: TI データシート SLVSD76C（2017 年 7 月改訂）。以下は原典（テキスト抽出）で確認した値。

| 項目 | 値 |
|---|---|
| 入力電圧 | 1〜5.5V（3.3V は範囲内） |
| 連続電流 | 2A |
| オン抵抗 | 53mΩ typ（3.3V、200mA）。最大 61mΩ（25℃）、80mΩ（105℃）。0.6A で約 32mV（typ）〜48mV（最大 80mΩ） |
| 静止電流（ON 時） | 8.3µA typ（3.3V） |
| シャットダウン電流（OFF 時） | 0.5µA typ、3.5µA max（3.3V） |
| ON ピン | アクティブ High。**「Do not leave floating」**。1V 以上の GPIO で駆動可。VIL 最大 0.5V |
| 立ち上がり時間 | CT ピンのコンデンサで調整。スルーレート SR = 0.55 × CT(pF) + 30 µs/V（10〜90%）。CT = 0 でも動作（Table 2） |
| 出力放電（QOD） | QOD ピンを VOUT につなぐと、OFF 時に内部抵抗で放電。浮かせると無効。外付け抵抗で調整可 |
| 入力コンデンサ | 1µF 以上（セラミック）を VIN と GND の間に |
| パッケージ | SOT-23-6（DBV）。ピン間隔 0.95mm |
| ピン | 1 VIN、2 GND、3 ON、4 CT、5 QOD、6 VOUT |

## 3. 回路案

```
Shield 3V3 ─┬────────────── VIN(1) ┐
            │                       │ TPS22918
         C1 1µF(セラミック)         │
            │                  GND(2)─── GND
           GND                      │
GPIO1 ─┬──────────────────────── ON(3)
       └── R1 100kΩ ── GND         │
                              CT(4)─── C2 1000pF ─── GND（立ち上がりを約 2ms に）
                              QOD(5)── （開放。下の注意を参照）
                              VOUT(6)──┬── U128 の VCC 線
                                       └── C3 0.1µF ── GND（任意）
```

- **R1（100kΩ のプルダウン）は必須。** データシートが ON ピンを浮かせることを禁じている。Deep Sleep 中に GPIO が Hi-Z になっても、OFF が保たれる。
- **C1（1µF 以上）** は、データシートの推奨条件。
- **C2（CT）**: 突入電流の制限用。SR = 0.55 × 1000 + 30 = 580µs/V で、約 2ms で立ち上がる。dV/dt ≒ 1700V/s なので、U128 の入力容量が 100µF なら突入電流は約 0.17A、470µF なら約 0.8A（U128 の入力容量は未確認）。2200pF（SR = 1240µs/V、約 4ms）にすれば、半分に下がる。ベンチで電流波形を見て決める。
- **QOD は初期状態では開放（無効）にする。** QOD を VOUT につなぐと、OFF 時に内部抵抗で VOUT を GND に引く。このとき、UART の TX 線が High のままだと、モデムの入力保護ダイオード経由で QOD の抵抗へ電流が流れ、MCU のピンと電池の電力を無駄にする可能性がある。一方、QOD を無効にすると OFF 時の VOUT が浮き、現行のリレーのように約 0.77V が残る可能性がある。**どちらがよいかはベンチで確認する**（項目 6）。
- **ON ピンの電圧**: GPIO は 3.3V なので、VIH（1V 以上）は十分に満たす。

## 4. 配線（試作段階）

現行のリレーと同じ、Grove ケーブル 2 本の構成を使う。

```
ケーブル B（Shield の D0 ポート → 小基板）
  赤   → VIN      （Shield の 3V3）
  黒   → GND
  黄   → ON       （GPIO1。100kΩ で GND へ）
ケーブル A（Shield の UART ポート → U128）の赤（VCC）だけを途中で切る
  U128 側の赤 ← VOUT
  Shield 側の赤は、使わず絶縁する
  黒・TX・RX はそのまま
```

- 試作は**ユニバーサル基板に手配線**する。TPS22918 は SOT-23-6 なので、変換基板（SOT-23-6 → 2.54mm ピッチ）を使う。
- 切る線は赤（VCC）だけで、現行のリレーと同じ。

## 5. ファームの変更（小さい）

`firmware/src/relay.cpp` を、パルス駆動から**レベル駆動**に変える。

- `initRelay()`: `pinMode(LTE_POWER_RELAY_PIN, OUTPUT); digitalWrite(..., LOW);`（OFF）。起動時の安全パルスは不要。
- `relayLteOn()`: `digitalWrite(..., HIGH);`
- `relayLteOff()`: `digitalWrite(..., LOW);`
- Deep Sleep 前に GPIO を LOW にしておく。R1 のプルダウンがあるので、Hi-Z になっても OFF が保たれる（`gpio_hold` は不要）。
- API 名（`relayLteOn` / `relayLteOff` / `initRelay`）と、`PSS_LTE_POWER_RELAY_ENABLED` のフラグは変えない。`PSS_RELAY_PULSE_MS` は不要になる。
- `relay.h` の注意書き（5V コイル、パルス幅）は、置き換え後に更新する。
- リレー版とロードスイッチ版の両方を残すかは未定（機体ごとにハードが違う期間がある）。

## 6. ベンチで確認する項目

1. **電圧降下**: 0.6A 負荷（ダミー負荷または U128 の送信時）で、VIN と VOUT の差が 50mV 以下か。
2. **突入電流**: ON 時の VIN の電圧と電流波形（U200 かオシロ）。CT = 1000pF と 2200pF を比較し、3V3 レールの落ち込みと、#74 のブラウンアウトへの影響を確認する。
3. **ON ピンの挙動**: GPIO が Hi-Z（Deep Sleep 突入時、書き込み中、リセット中）でも OFF が保たれるか。
4. **OFF 時のリーク**: 3V3 側の電流が、0.5µA 程度（TPS22918 の ISD）か。
5. **U128 の起動**: ON から AT 応答までの時間（現行のリレーは通電から約 5.5〜6.6s）。
6. **QOD の有無**: OFF 時の VOUT の電圧（開放で約 0.77V の残りがないか）。UART の TX を High にしたまま OFF にしたとき、TX から VOUT への回り込み電流（QOD ありの場合は、ピンに流れる電流）。
7. **CPOWD → OFF の順序**: SIMCom の HW Design 3.1.1 は、VBAT を直接切る前に、PWRKEY か AT で電源断することを勧めている。`disconnectTransport()` が CPOWD を送ってから OFF にする現行の順序を保つ。ブラウンアウトやウォッチドッグ再起動では、いきなり OFF になる（リレー版も、起動時の RESET パルスで同じ状況になる）。

## 7. 未確認・未決事項

- **U128 の入力容量**（突入電流の見積りに必要）。回路図は未取得。
- TPS22918 の**国内調達**（DigiKey JP、Mouser JP、秋月など）と価格。SOT-23-6 の変換基板の入手性。
- 秋月で売られているロードスイッチ IC（東芝 TCK106/107/108AF、5 個入り ¥150）は、電流や仕様の確認をしていない。手はんだしやすいパッケージかを含め、代替候補として未評価。
- **ポテンショメーターの扱い（2026-10-06 決定）: ブートモード後に抜く運用**（docs/60 §2.7、v5）。ロードスイッチにすると、リレーの 2ch でポットの VCC を切る方式が使えなくなるが、ポットは**つないでいる間（ブートモード中、最大約 4 分）だけ給電される**運用にする。
  - 現地でポットを回して値を決め、ブートモードが終わったら Grove ケーブルを抜く。値は NVS に保存済みで、通常サイクルは NVS の値だけを使う（ファームの変更は不要）。
  - **抜き忘れると、待機電流が約 0.3mA 増え続ける**（docs/60 §10.2）。LoRaWAN 版（リレーなし）も同じ運用。
  - 抜いたあとに物理的な電源サイクル（電池を抜く、完全な枯渇）が起きると、ブートモードが再発動して NVS が不定値で上書きされる。再調整や復旧は、ポットを挿し直してから電源を入れ直す（docs/60 §2.7）。
  - 将来、ティーチインボタンやクラウドからの設定に替える案は、必要が出たときに別 Issue で検討する。
- #87 の原因が Grove ケーブルの接触不良だった場合は、ロードスイッチにしても直らない。**VOUT 側のケーブルは、はんだ付けで確実につなぐ。**
- 最終形の**基板化**: Grove の入力・出力・制御の 3 コネクタを持つ小基板にすれば、ケーブルを切らずにすむ。ただし、設計の検証（KiCad の ERC/DRC、実機）は、試作でベンチ確認が済んでからにする。

## 8. 基板の試作（rev A、2026-10-05 発注）

試作の前に、ユニバーサル基板で確認する当初の計画（§4）から変更し、**Grove コネクタ 3 つ（IN / OUT / CTRL）を持つ小基板**を JLCPCB に発注した。ケーブルを切らずに挿すだけで済み、設計思想（Grove ケーブルだけで配線）に最も近い。

- 設計ファイル: [../hardware/lte-power-switch/](../hardware/lte-power-switch/)（KiCad 10.0.6、基板 38 × 28mm、2 層）。ERC・DRC とも違反 0 件。
- 発注: JLCPCB、PCB + 経済的な PCBA（トップ面）、各 5 枚。注文番号 W2026100516587610、2026-10-05。合計 $20.14（商品 $10.39 + 送料 $9.75。新規ユーザーのクーポンが効いた額）。
- 部品: TPS22918DBVR（C131941、Extended）、HY2.0-4P-WT（C722729、Extended）、1µF（C15849）、1nF（C1588）、100kΩ（C25803）。
- 注文画面の部品プレビューで、U1 の pin1 と J1〜J3 の pin1 の目印が、KiCad の設計と一致していることを確認した（2D 表示）。
- **DFM 分析（2026-10-06）:** 実装される部品は 7 点すべて（未実装 0 点）、DFM の警告なし。J1〜J3 と U1 の pin1 は、修正後の最終の配置でも設計と一致している。
  - 「Show Revised Items」で確認すると、**JLCPCB のエンジニアが修正したのは U1 の 1 点だけ**だった。修正の中身（回転か位置か）は画面では分からない。CPL の U1 の回転角（180°）に補正を入れていなかったため、向きを直してくれた可能性が高い（推測）。rev B を作るときは、CPL の U1 の回転角に補正が要る可能性がある。
  - 実装される部品の型番: U1 = TI TPS22918DBVR、C1 = Samsung CL10A105KB8NNNC（1µF）、C2 = Samsung CL10B102KB8NNNC（1nF）、R1 = UNI-ROYAL 0603WAF1003T5E（100kΩ）、J1〜J3 = CAX HY2.0-4P-WT。

### 届いたあとの確認（実機）

1. Grove ケーブルが J1・J2・J3 に嵌合するか。
2. 黄線のパッド（pin1）が、J1 と J2 で直結しているか（導通）。
3. J1 に 3V3 を入れ、J3 の黄を High にしたとき、J2 の赤が 3.3V になるか。GPIO を浮かせたとき OFF のままか。
4. §6 のベンチ確認項目。
