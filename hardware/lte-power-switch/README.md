# LTE power switch（Issue #88）

**状態: 暫定・WIP。rev A（2026-10-05 発注、2026-10-12 到着）は、Grove コネクタのピン番号が実物と鏡像のため、普通の Grove ケーブルでは使えない（下の「rev A の既知の不具合」）。このディレクトリの設計・製造データは、鏡像を直した rev B（2026-10-12 作成・発注）。** M5 Unit CatM（LTE-M）の VCC 線を TI TPS22918DBVR で開閉する、Grove コネクタ 3 つの小基板。設計の背景は [../../docs/88-load-switch-design.md](../../docs/88-load-switch-design.md)。

| コネクタ | 向き | 内容 |
|---|---|---|
| J1 IN | 左辺 | Shield の UART Grove ポートから。pin1/pin2 は J2 へ直結、pin3 = 3V3（`V3V3_IN`）、pin4 = GND |
| J2 OUT | 右辺 | LTE-M ユニットへ。pin1/pin2 は J1 から直結、pin3 = スイッチ後（`VLTE`）、pin4 = GND |
| J3 CTRL | 下辺 | Shield の D0（GPIO1）から。pin1 = `LTE_EN`（HIGH で ON）、pin4 = GND、**pin2/pin3 は未接続**（5V ポートに誤挿入しても被害が出ないように） |

Grove の pin1 = 黄、pin2 = 白、pin3 = 赤、pin4 = 黒。**物理的なパッドの並びは、三角（J1 は▼、J2 は▲、J3 は▶）のパッドから順に、pin4（黒・GND）、pin3（赤）、pin2（白）、pin1（黄）**（下の「rev B」の表）。基板は 38 × 28mm、2 層、1.6mm。部品はすべて表面（JLCPCB の片面実装）。

## rev A の既知の不具合（2026-10-12、実機で確認）

**J1・J2・J3 のコネクタ（HY2.0-4P-WT）の pad 番号が、実物と鏡像になっている。** Grove ケーブルを挿すと、▼（J2 は▲、J3 は▶）のマークに一番近いパッド（設計の pin1）に**黒（GND）**が来る。設計では、そこは pin1 = 黄（SIG1）。

| 位置（三角に近い順） | 設計（回路図・基板） | 実際にそこへ来る Grove ケーブルの線 |
|---|---|---|
| 1 番目（三角のパッド） | pin1 = SIG1（黄） | 黒（GND） |
| 2 番目 | pin2 = SIG2（白） | 赤（VCC） |
| 3 番目 | pin3 = 3V3 / VLTE（赤） | 白 |
| 4 番目 | pin4 = GND（黒） | 黄 |

- 回路図（論理）は正しい。誤りは、フットプリントの pad 番号（pad「1」を、実物の pin1 と逆の端に置いた）。
- 原因: 下の「発注前に確認すること」2 を、実物で確認しないまま発注した。
- 影響: 普通の Grove ケーブルを J1・J2 につなぐと、Shield の VCC と GND が信号線のパッドにつながる。**rev A を、普通のケーブルで Shield に挿さないこと。**
- rev A の使い方（検証のみ）: ケーブルの片側を切って、テストポイント（`3V3` / `GND` / `EN` / `VLTE`）に直結する。
- 直し方（rev B）: フットプリントの pad 番号を逆にする（1↔4、2↔3）。回路図は変えない。基板のコネクタまわりの配線は、引き直しになる。

**rev A の動作確認（テストポイント直結、2026-10-12）:** Shield の 3.3V を `3V3` TP に入れ、`EN` を `3V3` につなぐと、`VLTE` が 3.3V になった。外すと、1 秒以内に 0V に戻った（負荷なし、QOD 開放）。U1 の向きは正しい。

**LTE-M・実機ファームでの確認（2026-10-12）:** 逆結線の専用ケーブルで、Shield・U128 につなぎ、ブートモードの送信 2/5〜5/5（LTE-M の接続、MQTT）が、途中でリセットされずに完了した。OFF のときの `VLTE` は、UART が動いている間は約 0.76V（旧リレー方式と同程度）、Deep Sleep では、20〜30 秒で 0V になった。回路の変更は、要らない見込み。

**1 号機の実機での消費電力の実測（2026-10-13）:** Deep Sleep の待機電流は **平均 0.40 mA**（旧リレー方式は 0.45 mA）、送信 1 回は **0.42 mAh**（LTE の接続 7.5 秒）〜 1.14 mAh（接続 30.5 秒）。起床のたびに、スイッチは ON → OFF し、ブートモードの 5 回、状態変化の送信、定期送信（約 66 分ごと）が、すべて届いた。電圧降下（0.6A）と、突入電流の詳しい波形は、未確認（[docs/88-load-switch-design.md](../../docs/88-load-switch-design.md) §8）。

## rev B（2026-10-12 作成・発注）

rev A の鏡像の不具合を直した版。**回路図（論理）は rev A と同じ**で、変えたのは、フットプリントと配線と印字。

**変更点**
- コネクタ（HY2.0-4P-WT）のフットプリントの pad 番号を逆にした（1↔4、2↔3。rev A の実測で、実物の pin1 = 黄線は、+X 側）。
- コネクタまわりの配線を引き直した（V3V3_IN、VLTE、LTE_EN、SIG1、SIG2、GND のビア）。SIG1・SIG2 は、裏面の入れ子の U 字（交差なし）。TP2 は、VLTE の線の上に移した。U1・C1・C2・R1・R2・C3 と、J1〜J3 の位置・向きは、rev A と同じ（JLCPCB の CPL も同じ）。
- 三角（▼・▲・▶）の位置は、物理的に同じ。そこは GND（黒）のパッドになった。各コネクタの横に、「tri=GND(black)」と注記し、裏面に、全ピンの対応表を印字した。
- テストポイント（丸いパッド）は、rev A のまま。

**確認したこと（2026-10-12）**
- KiCad の DRC: 違反 0 件、未配線 0 件、回路図との不整合 0 件。ERC: 違反 0 件。
- `scripts/check_gerber_connectivity.py`: 製造用ガーバーから銅箔の接続を求め、10 ネットすべてが 1 つの塊で、ショートなし。J1〜J3 の物理的なパッド順が、実物の Grove ケーブルの順（三角から 黒・赤・白・黄）と一致する。**rev A のデータでは、同じチェックが、J1〜J3 で失敗する**（鏡像を検出できる）。
- 未確認: 実際に製造した基板での確認（rev A と同じ手順）。

**発注（2026-10-12）:** JLCPCB、PCB/PCBA、各 5 枚。注文番号 W2026101217460284、2026-10-12 18:46。商品 $20.90 + 送料 $9.71 = **$30.61**（rev A は $20.14。新規ユーザーのクーポンが効いていた額で、今回は効いていない）。内訳は、PCB（注文番号 Y3-13728224A）$2.00、実装 $20.48（注文画面の表示）。BOM・CPL・ガーバーは、`fabrication/` のデータ（BOM・CPL は rev A と同一）。

**注文画面（PCBA Viewer）での確認（2026-10-12）:** U1 の pin1（紫のマーク）は、左上のパッドで、rev A と同じ向き。

**物理的なパッド順（▼・▲・▶のパッドから順）と、印字**

| 位置 | J1（IN、Shield の UART へ） | J2（OUT、LTE-M へ） | J3（CTRL、Shield の D0 へ） |
|---|---|---|---|
| 1（三角のパッド） | GND（黒） | GND（黒） | GND（黒） |
| 2 | 3V3（赤） | VLTE（赤） | NC（赤。3V3 は未接続） |
| 3 | TX-6（白） | RX（白。モジュールの RX） | NC（白。D1 は未接続） |
| 4 | RX-7（黄） | TX（黄。モジュールの TX） | LTE_EN / D0（黄） |

- 三角は、**GND 側の端**（Shield の Grove ポートは、GND が端、その隣が 3V3）。
- J1 と J2 の信号線は、ケーブルがまっすぐなので、同じ位置にある。J1 は XIAO から見た名前（TX-6・RX-7）、J2 はモジュールから見た名前。
- **J3 の白（D1）は、NC のままにする。** Shield の右上ポート（D0・D1）の白線は、右下ポート（ポテンショメーター、D1・D2）の黄線と、同じ D1 の線。つなぐと、ポテンショメーターの信号に干渉する。赤（3V3）も、誤挿入しても何も入らないよう、未接続のまま。

**Shield（Grove Shield for XIAO）のポートの印字（2026-10-12、写真で確認。左から 1 番目〜4 番目 = 黄・白・赤・黒）**

| ポート | 黄 | 白 | 赤 | 黒 | 用途 |
|---|---|---|---|---|---|
| 左上（I2C） | SCL-5 | SDA-4 | 3V3 | GND | カラーセンサー |
| 左下（UART） | RX-7 | TX-6 | 3V3 | GND | J1 |
| 右上 | D0 | D1 | 3V3 | GND | J3 |
| 右下 | D1 | D2 | 3V3 | GND | ポテンショメーター |

- 左下の「RX」「TX」は、写真では頭文字が切れていて、ファームの定義（D7 = RX、D6 = TX）からの推定。

## 発注前に確認すること（rev A 発注時の項目。rev B の発注前にも、確認する）

1. **JLCPCB の注文画面（PCBA Viewer）で、U1 と J1〜J3 の向きを確認する。** rev A では、JLCPCB のエンジニアが、U1 の 1 点だけを修正した（修正の中身は不明。修正後の実装で、実機は正常に動作した）。rev B の CPL は、U1 と J1〜J3 の位置・向きが rev A と同じなので、同様に確認する。`fabrication/lte-power-switch-cpl.csv` の回転角は KiCad の値そのまま（補正なし）。フットプリントは LCSC/EasyEDA の公開ライブラリ由来なので補正が不要の可能性が高いが、自動では確認できていない。ずれていれば、注文画面で回転を直す。
2. **HY2.0-4P-WT が手元の Grove ケーブルと嵌合し、pin1 が黄線になるか。（rev A では、未確認のまま発注し、鏡像だった。rev B は、rev A の実物で確認した並びに合わせてあり、`check_gerber_connectivity.py` で検査できる。）** データシートに pin1 の位置の記載はなく、フットプリントの pin1（嵌合口を手前にして左端）は EasyEDA の定義による。最初の 1 枚で、ケーブルを J1 に挿し、反対側の黄線と基板の pin1 パッド（三角マーク側）の導通を確認する。
3. パッドの寸法は LCSC のライブラリ由来で、データシート（外形の図のみ）では検証できていない。
